### Checklist rules

Put them in `server/plan/checkPlan.ts`. They run at End, in parallel with the scorer. The result is saved on the lesson and **never added to the score**.

**Code rows:**
- **Check step:**
  - Done if a turn has checkType "question"; the quote is that turn's transcript.
  - Otherwise "not yet"; the next-time line is Omar's next_check.
- **Ask-by-name step:**
  - Done if a turn has askedKid set and checkType "question".
  - Partly if askedKid is set with any other check type.
  - If the step's text names a kid, only that kid counts.
  - Next time: "{name}، {that kid's next_check}" (Lina if no kid is named).
- **Challenge step:**
  - Done if Yazan reached level 2.
  - Next time: Yazan's next_check.
- **Repeated kinds** take matching turns in order.

**AI rows: explain, example, other.** One Claude call, using the scorer's model list and the same client helper and rules as the scorer (structured JSON output, no thinking param, no prefill). System prompt, verbatim:

```
You check a practice lesson against the teacher's own plan, for Sabboura, a teacher-training simulator with AI kids.
You receive JSON: the lesson language, some plan steps (each with a number, a kind and the teacher's planned text) and the lesson log (each turn's number and the teacher's exact words).
For EACH step, decide whether the teacher actually did it:
- evidence: first, copy the teacher's exact words from the ONE turn that best shows the step, or null.
- turn: that turn's number, or null.
- status: "done" if the words clearly do what the step says; "partly" if they touch it but are vague or incomplete; "not_yet" if no turn does it.
- next_time: for "partly" or "not_yet", one sentence (at most 15 words) the teacher could say to the class next time to do this step, in the lesson language; otherwise null.
Rules: use only the teacher's words; a step counts even if it came in a different order; quote only words that appear in the log; never judge the teacher as a person; in Arabic, write next_time in clear Modern Standard Arabic with light Jordanian warmth. Return only JSON that matches the schema.
```

- **Schema:** `{steps:[{step:number, evidence:string|null, turn:number|null, status:"done"|"partly"|"not_yet", next_time:string|null}]}`.
- **Quote check:**
  - Check every quote against that turn's transcript, with the same Arabic normalisation as the judge's evidence check (≥70% word overlap).
  - If it fails there, try the other turns.
  - If none match, set the row to "not yet" and log plan_evidence_mismatch.
- **Missing next_time:** explain uses Sara's next_check; example uses Khaled's.
- **If the call fails twice,** those rows show "—".

## PART 3 — The teacher uploads their own material

**Upload card on Home:**
- a drop zone and "choose file" (PDF, JPG, PNG or WebP, 10 MB max);
- "أو الصق النص / or paste the text" (12,000 characters max);
- an optional "Pages" field for PDFs (default: the first 6; 6 max);
- under it: "منقرأ الملف ومنحذفه، ومنحتفظ بالخطة بس. / We read your file, then delete it. We keep only the plan."

**Client:** resize photos so the long edge is at most 2000 px, as JPEG 0.88 (`createImageBitmap(file, {imageOrientation:'from-image'})`).

**Server:**
- POST /api/packs returns `202 {packId}` at once and runs a background job. GET /api/packs/:id returns `{status:'working'|'ready'|'failed', reason?}`.
- Check the file type from its first bytes.
- The pack id is sha1(content|language|pages), so the same file again is instant.
- Never store or write the file. Keep only the pack JSON, in a new `packs` table.
- **PDF:** keep the chosen pages with pdf-lib and send them as a Claude document block (base64, application/pdf).
- **Photo:** send it as an image block.
- **Text:** send it as a text block.
- Put the material first, then the instruction.

**The pack call:** one Claude call.
- Model: env CLAUDE_PACK_MODELS, falling back to the scorer list.
- `max_tokens` 8000, a 60 s timeout, one retry.
- The same client rules as the judge (structured output; anyOf for nullable fields).
- System prompt:

```
You prepare a practice lesson for Sabboura, a simulator where a teacher practises on five AI kids. You receive the teacher's material for ONE lesson and the lesson language. Write everything the teacher or kids will read in the LESSON LANGUAGE, even if the material is in another language. Base everything on the material; never contradict it.
- usable: false if it is not a lesson (blank, unreadable, a photo of people, unrelated); then return empty strings, empty arrays and nulls everywhere else.
- library_topic_id: "fractions" (comparing fractions), "negatives" (negative numbers) or "photosynthesis" ONLY if the material's main idea is exactly that topic, else null. If not null, set kids to null.
- title (≤6 words), title_en (English, ≤6 words), subject, grade (e.g. "4" or "7-8"), vocab (8–14 key words, comma-separated; for Arabic lessons also the main English terms).
- objective: one sentence starting "By the end, students can" / "في نهاية الحصة، يستطيع الطلاب".
- steps: exactly 5, in this order, each ≤18 words and specific to THIS material (its own numbers and examples): explain (the main idea WITH its reason), example (one real-life example or model, Jordanian everyday life where natural), check (one real question that needs an answer, in quotes), include (ask Lina, a quiet student, a short real question by name), challenge (a harder question for Yazan). In Arabic write steps as noun phrases ("شرح السبب: …"، "سؤال تحقق: «…»"), never commands.
- trouble_spots: exactly 3 short quotes of what a confused kid might say, matching omar's, lina's and sara's misconceptions, in kid language, without names.
- kids, each one FIXED slot: omar = the most common misconception about the main idea (research-known where possible), held confidently; lina = a second, more basic misconception a shy kid would never say out loud, fixed by making the idea concrete (picture, model, diagram, number line, object, everyday meaning); sara = knows the rule or fact from the material but not WHY; khaled = can't see where it's used in real life; yazan = already understands and needs a harder challenge.
  For each kid: misconception, helped_if (what the teacher must SAY to fix it, specific enough to check against a transcript), hurt_if (what makes it worse) — these three in ENGLISH; reveal (lesson language, ≤25 words: what the kid thought, then what would have reached them); next_check (lesson language: one question for next lesson, addressed to the kid; in Arabic use Jordanian dialect and the kid's gender: omar, khaled, yazan are boys; lina, sara are girls).
  Fixed patterns: sara misconception "Memorised <the rule> with no idea why.", helped_if "Gives the REASON (<the reason>), not only the rule.", hurt_if "Says 'just memorise it' or only repeats the rule."; khaled misconception "Can't see why <the topic> matters in real life.", helped_if "Uses a concrete real-life example (<two examples>).", hurt_if "Says it only matters for the exam."; yazan misconception "Already understands. Gets bored when the basics are repeated.", helped_if "Gives a harder challenge (e.g. <one>) or asks him to explain to the class.", hurt_if "Repeats the basics with nothing new."
No emojis. Return only JSON that matches the schema.
```

- **Schema:** `{usable, library_topic_id, title, title_en, subject, grade, vocab, objective, steps:[{kind,text}], trouble_spots:[string], kids:{omar,lina,sara,khaled,yazan: {misconception, helped_if, hurt_if, reveal, next_check}} | null}`.

**Build the pack:**
- **If library_topic_id is set:** use that ready lesson's researched topic and its trouble spots from plans.json, with the AI's plan.
- **Otherwise:** build a topic in exactly the topics.json shape:
